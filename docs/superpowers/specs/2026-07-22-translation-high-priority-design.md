# 翻译核心高优先级修复设计

## 目标

修复当前翻译链路中会导致任务失败、公式损坏或结构化文档损坏的高优先级问题，同时保持现有 API 响应、现代 Office 文件名和任务状态兼容。

本轮不实现旧版 `.doc`、`.xls`、`.ppt` 转换，也不支持百度翻译 PDF。

## 范围

### 文件策略

- 支持的 Office 文件限定为 `.docx`、`.xlsx`、`.pptx`。
- 单文件上传、批量 ZIP、MCP 上传和任务路由使用同一组扩展名策略。
- 旧版 Office 文件在提交阶段返回明确的“不支持旧版 Office，请转换为现代格式”错误，不进入翻译 worker。
- 当文件为 PDF 且服务为百度时，在任务创建校验阶段返回“百度翻译暂不支持 PDF”。

### Excel 与 CSV 公式保护

- Excel 提取单元格时跳过 `cell.data_type == 'f'` 的公式单元格，不将公式送入模型，也不覆盖公式。
- CSV 没有可靠的数据类型元数据，对去除首尾空白后以 `=` 开头的单元格按公式处理并原样保留。
- 公式单元格不计入翻译字数，不改变双语模式行为。

### HTML 回填

- 翻译结果不能直接拼接到序列化 HTML 字符串。
- 文本节点使用 DOM 节点回填，属性值继续通过属性对象回写；模型输出中的 `<`、`>`、`&` 必须作为文本或属性内容处理。
- 现有脚本、样式、代码等跳过规则保持不变。
- 回填失败时任务失败，不输出可能损坏的 HTML。

### Markdown 保护块

- 代码块、行内代码、公式、图片和链接 URL 继续使用占位符保护。
- 每个翻译块记录其要求保留的 `protected_tokens` 集合。
- 翻译结果必须保留每个 token 且不能引入未声明 token；缺失、重复或改写 token 均视为无效结果。
- 无效结果进入现有重试/备用模型流程；全部失败时任务失败且不生成目标文件。
- 成功结果按现有流程恢复保护块，保持 Markdown 结构和原始 URL。

## 数据流与错误处理

1. API 层根据文件扩展名和服务类型做前置拒绝。
2. 格式适配器提取可翻译单元，并标记公式或保护 token。
3. 统一翻译函数调用模型并执行结构校验。
4. 校验通过后，适配器回填并写入目标文件。
5. 结构校验或文件写入失败时，沿用现有失败状态更新，不写入不完整结果。

不改变现有非致命文本块失败即整批失败的策略，避免生成部分翻译文档。

## 测试设计

- 扩展名策略：单文件和 ZIP 均拒绝 `.doc/.xls/.ppt`；现代格式仍可路由。
- 服务策略：百度 PDF 在 API 校验阶段被拒绝，OpenAI PDF 路径不受影响。
- Excel：公式保持原值，普通文本仍进入翻译；CSV 公式字符串保持原值。
- HTML：包含 `<`、`>`、`&` 的译文仍是文本内容，属性值正确转义，原有标签结构可解析。
- Markdown：保护 token 完整时成功恢复；缺 token 时触发失败/重试，不留下占位符。
- 测试全部 mock 外部翻译服务，不依赖网络、API key 或 PDF 模型运行时。

## 非目标

- 本轮不重做统一文档中间表示。
- 本轮不处理 Word 文本框、脚注、图片相对顺序、PPT 图表文字、扫描 PDF 等中优先级问题。
- 本轮不修改前端构建产物。
