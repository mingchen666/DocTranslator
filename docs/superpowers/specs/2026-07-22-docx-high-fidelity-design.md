# DOCX 高保真翻译设计

## 目标

在保持现有翻译 API、任务状态和输出文件名兼容的前提下，提高 DOCX 在复杂排版下的结构保真度。翻译应只改变可翻译文本，不移动或删除图片、超链接、字段、换行、书签和文档关系。

本阶段先处理 DOCX；PPTX 在后续阶段复用 token、锚点校验和输出验收思路。

## 核心取舍

采用混合样式策略。有效样式相同的连续 run 合并为一个文本 span；存在粗体、颜色、超链接等视觉差异时，为各 span 插入不可变边界标记并整段翻译。边界标记校验通过后，译文 span 写回对应样式。若模型连续破坏样式边界，但结构锚点仍完整，则降级为主样式整段译文；图片、超链接、字段和书签不得降级或移动。翻译可读性优先于机械地按原语言词数映射样式边界。

## 中间表示

统一将正文段落、表格单元格、页眉和页脚解析为 inline token 序列。token 类型包括：

- `text`：可翻译文本，按有效视觉样式合并为 span，保存原文、样式引用和逻辑位置。
- `hyperlink`：超链接容器及 URL 关系，保留关系 ID，只翻译可见文本。
- `image`：图片或绘图 XML，原样保留并维持位置。
- `field`：页码、日期、目录等字段，原样保留。
- `break`：换行、分页和段落边界，原样保留。
- `bookmark`：书签开始/结束标记，原样保留。

每个翻译单元携带稳定的 token ID 和 `protected_tokens`。模型只接收逻辑段落文本及不可变占位符，返回后必须通过锚点完整性校验。

## 数据流

1. 翻译模块备份当前 `backend/app/translate` 下全部 Python 文件，保留相对目录结构。
2. 解析 DOCX 包中的正文、表格、页眉和页脚，建立 token 序列。
3. 仅提取 `text` token 翻译；超长内容只在文本 token 边界切分，不能拆断锚点。
4. 统一翻译层分别校验结构锚点和样式边界标记；结构锚点失败必须重试，样式标记失败可在重试耗尽后降级为主样式。
5. 将译文写回原 token 位置：单一样式段落复用原 run，多样式段落按已验证的 span 边界重建文本 run，不重建整个 DOCX 包。
6. 保存目标文件后重新用 `python-docx` 打开，并检查核心 XML 和关系可加载。

## 样式与模式

- 仅译文模式：保留原段落格式；单一样式段落保留原样式，多样式段落优先按 span 边界恢复，校验失败时使用第一个有效文本样式作为主样式。
- 双语模式：原文 token 保持不变，在原文本后追加换行和译文 token；锚点不复制到译文文本中。
- 继承格式模式：不清空整个段落或单元格 XML，只替换可翻译文本节点。
- 字体调整仅在译文明显变长且必要时执行，不能覆盖原有颜色、粗体、斜体、下划线和超链接关系。

## 错误处理

- 译文锚点校验失败时，沿用现有重试和备用模型流程。
- 重试耗尽或回填失败时，任务失败且不生成不完整目标文件。
- 无法识别的 XML 节点保持原样并记录告警，禁止静默删除。
- 输出无法重新打开或关系损坏时删除目标文件并标记任务失败。

## 验收测试

使用真实 DOCX fixture 覆盖：

- 多 run 的粗体、斜体、颜色、字体和混合样式段落。
- 超链接、图片前后文本、字段、换行和书签。
- 表格、合并单元格、页眉页脚和多节文档。
- 仅译文、双语和继承格式三种模式。
- 长文本切分与 token 恢复。

每个 fixture 检查：文本没有丢失、锚点顺序不变、图片和关系仍可加载、输出可以重新打开；失败场景检查不留下半成品。

## 非目标

- 本阶段不处理旧版 `.doc` 文件。
- 本阶段不重写 PPTX；PPTX 的图表、SmartArt 和几何布局另行设计。
- 本阶段不保证 Word 文本框、脚注和批注的完整编辑支持，除非它们能通过当前 XML token 解析路径安全识别；无法识别时保持原样并告警。
