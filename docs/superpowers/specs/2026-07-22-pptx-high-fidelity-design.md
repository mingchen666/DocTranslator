# PPTX 高保真翻译设计

## 目标

在保持现有翻译 API、任务状态、输出文件名和 `.pptx` 路由兼容的前提下，提高复杂演示文稿的翻译质量与结构保真度。翻译只改变明确支持的可见文本，不改变幻灯片尺寸、形状几何、对象层级、分组、旋转、图片或其他非文本对象。

本阶段覆盖普通文本框、占位符、组合形状和表格中的文本。图表与 SmartArt 内部文字不翻译，但其对象、关系和可见内容必须完整保留。

## 核心取舍

采用带保护标记的整段翻译。一个逻辑段落即使被 PowerPoint 拆成多个 run，也作为完整上下文提交给翻译模型；样式变化、超链接、字段和软换行通过不可变标记记录。译文通过标记校验后，再按原结构写回。

这种策略优先保证译文语义连贯，同时尽可能让粗体、斜体、颜色、字号、字体和超链接落在对应译文片段。不能采用逐 run 翻译，因为它会破坏句子上下文；也不能只按字符比例把整段译文切回原 run，因为语言语序变化后会把样式或链接套到错误文字上。

## 组件边界

新增独立的 PPTX 行内结构模块，负责：

- 将段落解析为行内计划，并记录文本 span、样式、结构锚点和原 XML 位置。
- 生成翻译文本及唯一保护标记。
- 分别校验样式边界和结构锚点。
- 将已验证译文写回原段落，或在允许时使用主样式降级。

`powerpoint.py` 继续负责文件入口、幻灯片与形状遍历、翻译批次协调、双语页复制、文本适配和输出验收。翻译协议与 run 重建细节不继续堆叠在入口模块中。

## 中间表示

每个文本框和表格单元格按段落建立独立行内计划。计划至少包含：

- `text`：可翻译文字，按连续有效视觉样式合并为 span。
- `style_boundary`：粗体、斜体、下划线、颜色、字号、字体、语言等有效样式发生变化的位置。
- `hyperlink`：run 级超链接容器和关系目标；只翻译可见文字，不改变关系。
- `field`：日期、页码等 `a:fld` 节点，原样保留。
- `break`：软换行、制表符等段落内结构，保持原有顺序。
- `unknown_anchor`：无法安全解释但必须保留的非文本节点，原样保留并记录告警。

每个标记在当前翻译单元内唯一。译文必须保留要求的标记集合、数量、嵌套关系和合法顺序，且不能引入未声明标记。

## 数据流

1. 在首次修改 PPTX 翻译代码前，重新备份当前 `backend/app/translate` 下全部 Python 文件，保留相对目录并校验哈希。该备份必须包含已经完成的 DOCX 高保真实现。
2. 遍历普通形状、占位符、组合形状和表格，按段落建立行内计划。图片、图表、SmartArt、媒体和 OLE 对象不提取文本。
3. 将完整逻辑段落及保护标记交给现有批量翻译流程。超长段落只能在安全文本边界切分，不能拆断结构锚点或样式区间。
4. 校验返回标记。验证通过后，按行内计划将译文写回原段落；表格保持原单元格和多段落结构。
5. 仅译文模式直接处理原页。双语模式完整复制原页，在复制页上通过稳定形状 ID 定位对象并写入译文，不再通过几何距离或形状顺序猜测映射。
6. 保存目标文件后重新打开 PPTX，并执行页面、形状和关系完整性检查。验收失败时删除目标文件并让任务失败。

## 版式策略

以下属性在单语译文页和双语译文页上均被冻结：

- 幻灯片尺寸与页面顺序；双语模式只按约定插入译文页。
- 形状的 `left`、`top`、`width`、`height`、旋转、层级、分组和裁剪。
- 表格位置、尺寸、行列结构、合并关系和单元格边距。
- 图片、背景、图表、SmartArt、媒体、OLE 对象及其关系目标。
- 文本框边距、垂直对齐、段落对齐、缩进、项目符号、行距和原有自动换行规则。

默认保留每个 run 的字号继承关系。只有译文容量估算表明可能放不下时，才在文本框级写入 DrawingML `a:normAutofit` 缩放比例，使显式字号和从主题、母版、版式或占位符继承的字号按同一比例缩小。缩放比例不得低于原字号的 60%；能够确定显式字号时还应保持不低于 `10pt`。不得通过扩大、移动形状或移动相邻对象解决溢出。

译文目标若原先使用 `SHAPE_TO_FIT_TEXT`，必须改为 `TEXT_TO_FIT_SHAPE`，阻止 PowerPoint 打开文件后根据译文自动扩大形状。双语模式只调整译文页，原文页的自动适配设置保持不变。原本已经使用 `TEXT_TO_FIT_SHAPE` 的文本框不得被放大，最终缩放比例取原设置与新估算中更小的值。

达到字号下限后仍可能放不下时，必须保留完整译文，让 PowerPoint 按原文本框规则换行或显示。不得截断、省略、隐藏文字，也不得为追求无溢出而改变页面布局。

容量估算与翻译逻辑分离，按文本框可用宽高、边距、字号、段落级别和目标语言字符宽度估算。它用于决定是否缩小字体，不对形状几何做修改，也不宣称代替 Office 的真实排版引擎。

## 样式与字体

- 样式相同的相邻 run 可以合并为一个 span，减少无意义的模型标记。
- 样式不同的 span 通过边界标记恢复；样式应落在对应语义片段，而不是按译文字符数机械切割。
- 目标语言字体兼容处理只能补充缺失或明显不兼容的字体设置，不覆盖已有兼容字体、颜色、粗斜体、下划线或字号比例。
- 添加东亚字体节点时必须遵守 DrawingML 子节点顺序，`a:ea` 位于 `a:latin` 之后、`a:hlinkClick` 和 `a:hlinkMouseOver` 之前，避免超链接 run 触发 Office 修复。
- 段落级格式和项目符号保留在原段落节点上，不通过清空文本框或重建整个段落树实现写回。

## 双语页复制

双语模式保留原文页不变，并在其后插入译文页。复制时深拷贝形状 XML，并重映射图片、超链接、图表、媒体、OLE 和其他引用关系。源形状的非视觉 ID 在复制页中保持稳定且唯一，因此译文块通过形状 ID 和段落位置直接定位。

不再使用几何距离和兜底顺序匹配。若复制页缺少目标形状 ID、存在重复 ID，或形状类型与源页不一致，则该文档失败，避免把译文写入错误对象。

## 错误处理

- 样式边界标记损坏时沿用现有重试能力。重试耗尽但所有结构锚点完整时，可将完整译文写入该段落的主样式 span；主样式按有效文本覆盖范围选择。
- 超链接、字段、软换行或未知结构锚点缺失、重复、乱序或嵌套非法时，不允许样式降级。重试耗尽后任务失败。
- 无法安全解析的形状或 XML 节点保持原样并记录告警，不得静默删除。
- 双语页复制、关系重映射、译文写回或保存后验收任一阶段失败时，不交付部分成功文件。
- 若目标文件已创建但最终验收失败，删除目标文件并通过现有任务错误通道返回明确原因。

## 输出验收

保存后使用 `python-pptx` 重新打开目标文件，并检查：

- 页数及单语/双语页面顺序符合模式要求。
- 每页形状 ID 唯一，源页与译文页的目标形状 ID 和类型可对应。
- 所有原有图片、背景、图表、SmartArt、媒体、OLE 和超链接关系仍可解析，外部关系目标未变化。
- 形状和表格几何与基准记录一致。
- 输出中不存在内部保护标记，支持的可翻译段落没有被截断或遗漏。

验收目标是对象语义和视觉结构一致，不要求 ZIP 包字节级一致。Office 包内部关系 ID、XML 顺序或压缩结果可以变化，但不能造成对象丢失、错位、串写或文件不可打开。

## 验收测试

使用真实 PPTX fixture 和 mock 翻译结果覆盖：

- 同一段落内混合粗体、斜体、颜色、字号、字体和下划线。
- run 被任意切碎但逻辑上属于同一句话。
- run 级超链接、字段、软换行、空段落、项目符号和多级缩进。
- 单元格多段落、混合样式、合并单元格和表格边距。
- 普通形状、占位符、重叠形状、相同几何形状和多层组合形状。
- 图片、背景图、图表、SmartArt、媒体和 OLE 对象的关系保留。
- 仅译文与双语模式下的页面顺序、原文页不变、稳定 ID 映射和关系目标。
- 中英、中日等长度差异明显的译文，以及达到最小字号后仍无法完全容纳的极端译文。
- 继承字号为 `None` 的占位符、`SHAPE_TO_FIT_TEXT` 文本框、已有 `TEXT_TO_FIT_SHAPE` 缩放比例及混合显式字号。
- 中文超链接 run 中 `a:latin`、`a:ea` 与 `a:hlinkClick` 的 XML 顺序。
- 模型删除、重复、改写、乱序或伪造保护标记时的重试、主样式降级与结构失败。
- 保存后重新打开、关系遍历和失败输出清理。

测试全部 mock 外部翻译服务，不依赖网络或真实 API key。除自动测试外，至少保留一组可用 PowerPoint 或兼容 Office 打开的人工验收样例，用于确认图片、对象层级和文本显示没有明显回归。

## 非目标

- 不处理旧版 `.ppt` 文件。
- 不翻译图表、SmartArt、媒体或 OLE 对象内部文字。
- 不移动、扩大或重新排列任何形状来适应译文。
- 不引入 PowerPoint/LibreOffice 服务端渲染依赖，也不承诺像素级自动渲染等价。
- 不修改翻译 API、前端交互、任务队列或其他文档格式的行为。
